# ucenka-vi.ru — Пикалка

Статический сайт на GitHub Pages: сканируешь штрихкод — получаешь рубрику и
себестоимость (уценка) или кластер (предсорт). Сервера нет, весь поиск идёт в
браузере.

## Как устроен поиск

База лежит в `data/v2` и режется на **шарды по последним четырём цифрам
штрихкода** — 10 000 файлов примерно по 30 КБ. Поиск по штрихкоду — это один
запрос за одним таким файлом, без всякой подготовки: ~30 КБ и единицы
миллисекунд на разбор.

Уценка и предсорт живут **в одном шарде**. После перехода на
`Пикалка_ЕДИНАЯ.sql` набор штрихкодов у них общий, поэтому переключение вкладки
ничего не скачивает — меняется только то, какое поле показано.

Поиск по наименованию идёт через инвертированный индекс в `data/v2/words`:

* `words/{две буквы}.txt.gz` — редкие слова и их штрихкоды, обычно 1–3 КБ;
* `words/big/w-{слово}.txt.gz` — слова, встречающиеся чаще 500 раз (бренды вроде
  `bosch`). Без длинных списков запрос из двух частых слов не с чем пересекать.
  Префикс `w-` нужен, чтобы слова вроде `con` или `aux` не упирались в
  зарезервированные имена Windows.

Запрос из нескольких слов пересекает списки, а слова ищутся в любом порядке:
в базе товар записан как «Bosch Перфоратор», а спрашивают обычно наоборот.

### Что было раньше

База лежала как 15 частей по 21 МБ плюс bloom-фильтр на 12 МБ. Чтобы ответить на
один штрихкод, браузер скачивал 12 МБ индекса и 21 МБ части, распаковывал её в
58 МБ и линейно сканировал — всё в главном потоке. Поиск по наименованию читал
базу целиком, до 300 МБ на запрос. Отсюда и были жалобы на тормоза.

## Обновление базы

1. Выгрузить `E:\Work\Пикалка\Пикалка_ЕДИНАЯ.sql` в CSV:

   ```
   py "E:\Work\Инструменты\sqlq.py" -f "E:\Work\Пикалка\Пикалка_ЕДИНАЯ.sql" --csv "E:\Work\Выгрузки\ГГГГ-ММ\пикалка_единая.csv" --max-rows 20000000 --timeout 10800
   ```

2. Пересобрать индекс (займёт около получаса, из них почти всё — сжатие):

   ```
   py tools/build_index.py "E:\Work\Выгрузки\ГГГГ-ММ\пикалка_единая.csv"
   ```

3. Закоммитить `data/v2` и запушить. Файлы пишутся без отметки времени, поэтому
   неизменившиеся шарды не создают новых объектов в git.

Дашборд антигенерации обновляется отдельно —
`E:\Work\Инструменты\Автоматизация\07 — Обновление сайта антигенерации.py`,
поиска он не касается.
